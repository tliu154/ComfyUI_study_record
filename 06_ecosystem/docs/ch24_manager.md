### 24.1 为什么需要 Manager（Why Manager）

**概念定义**：ComfyUI 的核心节点覆盖「加载→编码→采样→解码」这条主干，
但 ControlNet、IP-Adapter、Ultimate SD Upscale、AnimateDiff、各种模型加载器……
这些都是社区开发者做的**自定义节点包（Custom Node Pack）**，需要额外安装。
**ComfyUI Manager** 是一个自定义节点，专门帮你 managed 其它自定义节点——相当于插件管理器。

**直觉类比**：ComfyUI 本体像**智能手机**，自带电话、短信等基础 App；
自定义节点像**应用商店里下载的 App**，想要新功能就去装。
Manager 就是那个**应用商店本身**——搜索、安装、更新、卸载都在这里一条龙。
前面你用到的 [ch13 ControlNet](../../03_control_and_refine/docs/ch13_controlnet.md)、
[ch14 IP-Adapter](../../03_control_and_refine/docs/ch14_reference.md) 背后都依赖自定义节点包。

**界面 / 参数**：装好 Manager 后，ComfyUI 顶部菜单会多出这些入口——
- `Manager` 主菜单：进入管理面板
- **Custom Nodes Manager**（自定义节点管理）：搜索/安装/更新/卸载节点包
- **Install Missing Custom Nodes**：一键安装当前工作流缺少的节点
- **Model Manager**：查看模型文件（部分版本有）

**常见误区**：
- ❌「ComfyUI 下载就自带所有节点」—— 不。核心节点之外大多要自己装，教程里的节点你画布上没有，通常就是缺包。
- ❌「Manager 是官方强制组件」—— 它是社区项目，但已是事实标准，强烈建议第一个装。
- ❌「自定义节点和模型是一回事」—— 不是。节点包是 Python 代码（放在 `custom_nodes/`），模型是权重文件（放在 `models/`），两者完全不同（[ch18](../../04_models_and_lora/docs/ch18_model_files.md)）。

> **够用边界**：记住「新功能 = 装自定义节点包，Manager = 管这些包的应用商店，代码放 `custom_nodes/`」即可。
> Manager 内部实现、`comfy registry` 协议细节不用管。
> **和已有认知的差异**：如果你用过 Automatic1111 的一键脚本装扩展，Manager 是同类思路，但更集成——
> 能直接从报错/工作流反推「缺哪个包」并一键安装，这是 WebUI 里要手动翻 GitHub 才能做的。

### 24.2 安装、搜索、更新节点包（Install / Search / Update）

**概念定义**：Manager 的日常操作就四件事：装 Manager 本身、搜索并安装节点包、更新、卸载。
节点包本质是一个 Git 仓库，Manager 帮你 clone 到 `custom_nodes/` 并处理依赖。

**直觉类比**：像用**手机应用商店**——
搜索框输名字 → 点安装 → 有更新红点就点更新 → 不用了就卸载。
唯一区别是有些包装完要**重启 ComfyUI** 才生效（App 装完要重启手机）。

**界面 / 参数**：典型流程（菜单名随版本略有差异）——
```
安装 Manager 本身（二选一）：
  ① 手动：git clone 到 custom_nodes/ComfyUI-Manager，装完重启
  ② 用 comfy-cli：comfy node install ComfyUI-Manager（见 ch23 23.4 / ch25）

装其它节点包：
  Manager → Custom Nodes Manager → 搜索关键词
  → 点 Install → 按提示重启 ComfyUI

更新：Custom Nodes Manager → Update All（或单个更新）
卸载：找到包 → Uninstall → 重启
```
- 目录位置：`ComfyUI/custom_nodes/<包名>/`
- 装完按 `R` 或重启刷新；浏览器缓存有时也要刷一下（`Ctrl+F5`）

**常见误区**：
- ❌「装完立刻能用」—— 很多包要重启 ComfyUI 才加载新节点；不重启画布上就找不到。
- ❌「Update All 永远安全」—— 大版本更新可能破坏工作流兼容性；稳定后先别无脑全更（见 24.4）。
- ❌「搜不到 = 没有这个包」—— 有些包不在默认索引里，需要填 GitHub 仓库地址手动装（Manager 支持 URL 安装）。

> **够用边界**：会「搜索→安装→重启→在画布搜到节点」这条闭环就够。
> 依赖冲突、pip 装依赖的细节遇到问题再说。
> **和已有认知的差异**：Manager 装的是**代码**，不是模型权重。
> 很多人以为装了 ControlNet 节点包就能用，结果还缺 controlnet 模型文件——节点和模型要分别搞定。

### 24.3 「节点缺失」排查（Missing Nodes）

**概念定义**：打开别人分享的工作流时，画布上出现**红色/高亮的缺失节点**，或队列报错
`Node type not found`，意思是这条工作流用到的某个自定义节点包你没装。
Manager 能列出缺哪些、尝试一键安装。

**直觉类比**：像打开一个用**别人手机上的 App** 做的文档——
文档里引用了某个 App 的功能，你手机上没装那个 App，就看不了那部分。
Manager 的「Install Missing Nodes」就是「自动帮你把这些 App 装上」。

**界面 / 参数**：排查步骤——
1. **看提示**：打开工作流后，ComfyUI 通常会弹「Missing Nodes」列表，或顶部有红字提示
2. **一键装**：`Manager → Install Missing Custom Nodes` → 勾选 → Install → 重启
3. **手动兜底**：若自动装失败，看缺失节点的**包名**（注意：节点类名 ≠ 包名），
   去 Manager 搜索或从报错信息/GitHub 找对应仓库手动装
4. **装完仍缺**：确认重启了、确认包真的装到 `custom_nodes/`、刷新浏览器

**常见误区**：
- ❌「红色节点 = 模型缺失」—— 红节点通常是**节点包**缺失；模型缺失是另一类报错（运行时才报，见 [附录 C](../../90_appendix/docs/appC_troubleshooting.md)）。
- ❌「节点名搜得到就行」—— 搜索要用**包名**，节点类名（如 `KSampler`）往往和包名不同；一键安装帮你绕开这个问题。
- ❌「一键安装 100% 成功」—— 冷门包、改名包、依赖冲突时会失败，需要手动查仓库。

> **够用边界**：掌握「看缺失列表 → 一键装 → 重启 → 还缺就手动查包名」这条流程即可。
> **和已有认知的差异**：节点式工作流**依赖外部环境**——
> 分享一条 `.json` 工作流不等于分享了一个能直接跑的东西，对方还得装齐对应的节点包和模型。
> 这是节点式生态相比「一张图片文件」的天然代价。

### 24.4 安全与版本锁定（Security & Pinning）

**概念定义**：自定义节点是**别人写的、在你机器上运行的 Python 代码**——
装包等于授予它执行权限，所以有安全和稳定性风险。
「版本锁定」指把节点包固定到某个已知能用的版本，避免自动更新后工作流崩掉。

**直觉类比**：装 App 要看**开发者可信不可信**、别乱给权限；
节点包同理——装来源不明的包，等于让陌生代码在你电脑上跑。
而「自动更新」像 App 自动升级到测试版——新版本可能有 Bug，稳定环境里往往**故意不更新**。

**界面 / 参数**：实用建议——
- **看来源**：优先装知名/高星仓库；Manager 里显示来源，陌生包先查一下
- **别无脑 Update All**：生产/稳定工作流跑通后，记录当前版本，非必要不更新
- **版本锁定**：需要时进 `custom_nodes/<包名>` 目录用 git 切到固定 commit/tag
- **备份**：批量更新前备份 `custom_nodes/` 列表和你常用的工作流 JSON
- 企业/长期项目：把「节点包 + 版本 + 模型」一起纳入版本管理

**常见误区**：
- ❌「社区包都安全」—— 大多没问题，但供应链风险真实存在；陌生包装前查来源。
- ❌「版本越新越好」—— 更新可能改变节点行为、删节点，导致老工作流打不开。稳定就是好事。
- ❌「Manager 会自动帮我回滚」—— 不会。更新前自己留后路。

> **够用边界**：记住「节点包=可执行代码，装前看来源；稳定环境别乱更新，更新前备份」两条安全常识。
> git 锁版本、依赖审计的细节进阶再说。
> **和已有认知的差异**：图像阶段你可能只关心「模型从哪下载」；
> 进入生态篇后，**「代码从哪来、会不会变」**成了新的关注点——这是从使用者到工程使用者的意识升级。

## 小结

- 自定义节点包提供核心之外的新功能，装代码放 `custom_nodes/`；Manager 是管这些包的应用商店。
- 日常闭环：搜索 → 安装 → **重启生效** → 画布搜到节点；更新卸载同理。
- 节点缺失 = 缺自定义节点包（不是缺模型）：看缺失列表 → 一键装 → 重启 → 兜底手动查包名。
- 安全常识：节点包是可执行代码，装前看来源；稳定环境别无脑更新，更新前备份、必要时锁版本。
