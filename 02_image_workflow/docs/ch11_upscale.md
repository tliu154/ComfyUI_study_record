# 第 11 章 放大与高清修复（Upscaling & Hires-fix）

**一句话**：想出高分辨率大图，**别直接把尺寸填很大**（会畸形）——
先用推荐尺寸出一张好底图，再**放大 + 二次采样补细节**（高清修复 Hires-fix），又快又稳。

### 11.1 为什么要分两段生成

**概念定义**：直接在 `Empty Latent Image` 填 2048×2048 生成，通常会出问题——
模型没在这么大分辨率上训练，会出现**重复物体、构图崩坏、肢体畸形**。
正确做法（Hires-fix，高清修复思路）：
1. 先按模型推荐尺寸（SD1.5 512、SDXL 1024）生成一张**构图正确**的底图
2. 再放大这张底图，用**较低的 denoise 二次采样**，在保持构图的同时补出细节

**直觉类比**：像**画油画**——
你不会一上来就在 2 米画布上画精细人体（比例容易崩），而是先在小画布上打好构图草稿，
确认无误后再放大到巨幅、细细刻画细节。两段走，稳。

**界面 / 参数**：两段 vs 一段对比——
| 做法 | 结果 |
|---|---|
| 一段：直接 2048×2048 | 构图崩、重复头、慢、爆显存 |
| 两段：512 出图 → 放大 → 二次采样 | 构图保持、细节丰富、可控 |

**常见误区**：
- ❌「分辨率越高越清晰，直接填大尺寸」—— 这是新手最常犯的错，见 [ch07 7.4](../../01_core_nodes/docs/ch07_latent.md#c07-04)。
- ❌「放大只是把像素拉大，不会变清晰」—— 单纯插值（如最近邻）确实不增细节；
  但 Hires-fix 的**二次采样**会真正生成新细节，这是关键区别。

> **够用边界**：记住「**先小图出构图，再放大 + 二次采样补细节**」这个两段式。
> **和已有认知的差异**：普通图像放大（插值/超分）是**纯图像处理**，不产生新的语义细节；
> Hires-fix 是让 diffusion **重新去噪生成**细节，等于「在放大后再画一遍」。这是生成式放大 vs 传统放大的本质区别。

### 11.2 LatentUpscale + 二次 KSampler

**概念定义**：最经典的高清修复工作流，是把第一次 KSampler 的 latent **放大**（`LatentUpscale`），
再送进**第二个 KSampler**用较低 denoise 采样，最后统一 VAE Decode 出图。

**直觉类比**：像**草稿 → 放大描稿 → 精修**——
第一个 KSampler 出草稿（latent），`LatentUpscale` 把草稿放大到更大画布，
第二个 KSampler 拿着低 denoise「轻轻重描」补细节（denoise 低=不大改构图），最后洗成照片。

**界面 / 参数**：接线骨架（Hires-fix 核心）——
```
【第一段：出底图】
Empty Latent Image(512×512) → KSampler #1 → latent

【第二段：放大 + 精修】
KSampler #1(latent) → LatentUpscale(samples)
  LatentUpscale 控件：upscale_method（如 nearest-exact / bilinear）、scale_by（如 2）
LatentUpscale(latent) → KSampler #2(latent_image)
  KSampler #2：denoise 设低（0.4~0.6），seed 可与 #1 相同或固定
KSampler #2(latent) → VAE Decode → Save Image
```
两个 KSampler 共用同一个 MODEL 和 conditioning（正负提示词）。

关键参数：`scale_by`（放大倍数，如 2 → 512 变 1024）、`upscale_method`（放大算法）、
第二个 KSampler 的 `denoise`（越低越保构图，越高细节变化越大）。

**常见误区**：
- ❌「第二个 KSampler 的 denoise 也设 1」—— 那会把构图重画掉。要设低（0.4~0.6）。
- ❌「放大倍数随便填很大」—— 2 倍常见；一次放太大仍可能出问题，可多次小步放大。
- ❌「两段用了不同模型/提示词」—— 通常共用同一套，保持风格一致。

> **够用边界**：会照骨架接出两段工作流、知道第二个 KSampler 的 denoise 要调低就够了。
> `upscale_method` 各算法差异、潜空间插值的数学跳过。
> **和已有认知的差异**：这里**两个 KSampler 串联**，第一次的输出（latent）是第二次的输入——
> 和我们前面「一个 KSampler 一条工作流」不同，但本质还是那条链，只是重复了一次。理解了这点，多重采样、迭代细化都是同一个套路。

### 11.3 用放大模型补细节

**概念定义**：除了在 latent 空间放大（11.2），另一类做法是在**像素空间用专门的放大模型（ESRGAN 等）**补细节，
节点如 `Upscale Image`（配 `Upscale Model Loader`）。常见组合：latent 放大 → VAE Decode → 像素放大模型 →（可选）再细化。

**直觉类比**：11.2 的 latent 放大是「让画家在放大稿上重画细节」；这里的放大模型是「用一台专业超分扫描仪」，
它专门学过怎么把小图变清晰、补出锐利细节，不靠 diffusion 重画。

**界面 / 参数**：两种方式对比——
| 方式 | 节点 | 特点 |
|---|---|---|
| 潜空间放大 + 二次采样 | `LatentUpscale` + KSampler #2 | 生成式补细节，能改内容，Hires-fix 主流 |
| 像素放大模型 | `Upscale Model Loader` + `Upscale Image` | 超分锐化，细节"长出来"但不动语义；常配合前者 |
| 社区加强节点 | 如 Ultimate SD Upscale（自定义节点） | 分块放大，能出超大图，需装插件（[ch24](../../06_ecosystem/docs/ch24_manager.md)）|

放大模型文件放 `models/upscale_models/`，按 `R` 刷新（同 [ch05 5.3](../../01_core_nodes/docs/ch05_loaders.md#c05-03)）。

**常见误区**：
- ❌「放大模型能当 checkpoint 出图」—— 不能，它只做放大，不生成内容。
- ❌「用了放大模型就不用二次采样」—— 可以只用放大模型（快），但结合二次采样细节更好；按需求组合。

> **够用边界**：先掌握 11.2 的 latent 放大（不用装额外模型）；想要更锐利再上放大模型。
> 分块放大（Ultimate SD Upscale）是进阶，第 7 篇装 Manager 后再玩。
> **和已有认知的差异**：放大模型是**判别式超分**（学到「清晰图长啥样」），diffusion 二次采样是**生成式重绘**（凭提示词造细节）。
> 一个保真、一个有创造性，常搭配用。

### 11.4 显存与耗时权衡

**概念定义**：放大是显存和耗时的放大器——分辨率翻倍，latent 面积约 4 倍，显存和耗时都显著上升。
超大模型/多次放大容易 OOM。

**直觉类比**：像**装修加楼层**——楼越大，材料和工期越多；地基（显存）不够就盖不高。
得在「想要多大」和「机器扛不扛得住」之间取舍。

**界面 / 参数**：省资源的办法——
- **分小步放大**：2 倍 ×2 次（512→1024→2048），比一次 4 倍稳
- **控制最终尺寸**：够用就好，别盲目上 4K
- **低显存模式**：见 [ch26](../../06_ecosystem/docs/ch26_performance.md)
- **少用多个放大模型串联**：每串联一步都吃显存
- **VAE 精度**：必要时用 fp16 VAE（[ch18](../../04_models_and_lora/docs/ch18_model_files.md)）

**常见误区**：
- ❌「OOM 就换更大显卡」—— 先试小步放大、降最终尺寸、低显存模式，通常能解决。
- ❌「放大不花时间」—— 二次采样 + 大 latent 明显更慢，要有心理预期。

> **够用边界**：记住「小步放大、尺寸够用就好、OOM 先降尺寸/开低显存」。
> 显存优化的底层机制跳过，见 [ch26](../../06_ecosystem/docs/ch26_performance.md)。
> **和已有认知的差异**：放大流程的瓶颈往往不是「会不会搭」而是「机器扛不扛」——
> 这是生成式 AI 的工程现实：算法人人会调，资源决定上限。

---

## 小结

- 别直接填大尺寸（会崩）；先按推荐尺寸出好底图，再放大 + 二次采样补细节（Hires-fix）。
- 经典做法：`LatentUpscale` 放大 latent → 第二个 KSampler（`denoise` 调低 0.4~0.6）→ VAE Decode。
- 也可用放大模型（ESRGAN）在像素空间超分锐化，放 `models/upscale_models/`。
- 显存/耗时随分辨率涨；小步放大、尺寸够用、OOM 先降尺寸/开低显存。
