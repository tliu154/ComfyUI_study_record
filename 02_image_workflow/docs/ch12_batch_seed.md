### 12.1 一次出多张：batch_size

**概念定义**：`batch_size` 是 `Empty Latent Image` 里的一个控件，表示**一次排队生成几张图**。
设为 4，点一次 Queue Prompt 就一次产出 4 张（seed 依次变化）。

**直觉类比**：像**批量冲印照片**——你不是一张张按快门，而是一次设定「印 4 张」，机器连着出。
但底片（latent）一次备 4 份，所以要占更多「显存台面」。

**界面 / 参数**：
- 位置：`Empty Latent Image` 节点的 `batch_size`（文生图）；
  图生图里则在 `Load Image` 批处理或用其它批处理节点
- 效果：batch_size=4，seed 会自动 incremental（如 42/43/44/45）
- 显存：batch_size 越大，显存近似线性增加，越大越容易 OOM

**常见误区**：
- ❌「batch_size 越大越省时间」—— 单张平均时间可能略降，但总耗时和显存都涨；显存不够会 OOM。
- ❌「batch 里每张都一样」—— 不会，seed 递增，每张不同（除非你把 seed 也锁死并禁用递增）。
- ❌「图生图也能直接在 Empty Latent Image 设 batch」—— 图生图起点是 Load Image，batch 机制不同，需另想办法。

> **够用边界**：知道「文生图在 Empty Latent Image 设 batch_size 一次出多张、别超显存」就够了。
> **和已有认知的差异**：这和你写循环 `for i in range(4): generate()` 效果类似，
> 但 ComfyUI 在**一个批次里并行处理**，比循环四次更高效地利用显卡——批处理是 GPU 计算的自然单位。

### 12.2 锁种子复现 vs 换种子探索

**概念定义**：seed 的两种用法对应两种目的（[ch08 8.2](../../01_core_nodes/docs/ch08_ksampler.md#c08-02) 已讲基础）：
- **锁 seed（固定）**：改其它参数做对照时，锁住 seed，保证「只有这一个变量在变」，结果可归因、可复现。
- **换 seed（随机/递增）**：同一套参数想多看几个变体，就换 seed 探索不同构图/细节。

**直觉类比**：
- 锁 seed = **控制变量实验**：其它条件不变，只调一个旋钮，看它到底起什么作用（科学方法）
- 换 seed = **多摇几次骰子**：配方不变，看能摇出哪些不同结果（创作探索）

**界面 / 参数**：KSampler seed 控件旁的按钮——
- 骰子图标：随机换一个 seed
- 锁/解锁：锁定后 Queue Prompt 不自动变 seed
- 递增模式（batch 时）：每张 seed +1

工作流建议：
- **调参数阶段**：锁 seed，一次只动一个变量（这也是 [ch08 实操](../../01_core_nodes/tasks/ch08_task.md) 的方法）
- **挑图阶段**：参数定了，批量换 seed 多出几张挑最好的
- **复现某张**：记下它的 seed + 全部参数，填回去即可重现

**常见误区**：
- ❌「调参时 seed 也让它随机」—— 那你就分不清是哪个参数导致的变化，实验白做。
- ❌「记了 seed 就能复现」—— 还要记模型、提示词、全部参数、节点版本；只记 seed 不够（[ch08 8.5](../../01_core_nodes/docs/ch08_ksampler.md#c08-05)）。

> **够用边界**：记住「**调参锁 seed、挑图换 seed、复现靠完整记录**」。
> **和已有认知的差异**：程序里随机数常被视为「要消除的噪声」；在生成式 AI 里 seed 是**可复现性的关键旋钮**，
> 要主动管理和记录，而不是随手 `random.seed()` 了事。

### 12.3 Primitive 驱动多处

**概念定义**：`Primitive` 节点是一个「万能值」节点，能输出不同类型的值（数字/字符串等）。
把它连到多个节点的对应输入，就能**用一个控件同时驱动多处**——改一处，所有连着的地方一起变。

**直觉类比**：像**总开关 / 遥控器**——
你不用挨个调 5 个节点里的 step，而是用一个「主控旋钮」连到它们，转一下全变。
像音响的「总音量」控制多个音箱。

**界面 / 参数**：典型用法——
- **参数扫描**：把 `Primitive` 设成 int，连到 KSampler 的 `seed`；配合脚本/循环改 Primitive 值，批量出不同 seed 的图（进阶见 [ch25](../../06_ecosystem/docs/ch25_api_automation.md)）
- **统一尺寸**：一个 Primitive 输出连到多个需要同尺寸的地方
- **提示词复用**：Primitive 设字符串，连到多个 CLIP Text Encode（少用，通常直接填）

操作：加 `Primitive` 节点，右键可切换输出类型；拖它的输出连到目标输入（类型要匹配，[ch04](../../01_core_nodes/docs/ch04_mental_model.md#c04-04)）。

**常见误区**：
- ❌「Primitive 能连任意输入」—— 不行，仍要类型匹配（int 连数字口，不能连 conditioning 口）。
- ❌「一个输入能接多个 Primitive」—— 不能，一个输入只接一根线（[ch04 连线规则](../../01_core_nodes/docs/ch04_mental_model.md#c04-04)）。

> **够用边界**：知道「Primitive = 一个值驱动多处，改一处全变」即可；上手先用在统一 seed / 尺寸。
> 用它做自动化参数扫描是第 7 篇 API 的事。
> **和已有认知的差异**：这像编程里的**变量/常量引用**——
> 一个值定义一次、多处引用，改一处全线生效。没它你得手动同步多个节点的相同值，容易漏。

### 12.4 给产出做记录

**概念定义**：批量出图后，**记录每张图的参数**（模型、seed、提示词、steps/cfg/sampler、尺寸）非常重要——
否则过几天你根本不记得某张好图是怎么出来的。

**直觉类比**：像**实验记录本 / 冲印底片袋**——
摄影师会在每张底片袋上写光圈快门，你也要给每张图留「配方卡」，才能复现和对比。

**界面 / 参数**：记录方式（选一）——
- **文件名带参数**：ComfyUI 保存的文件名通常含 seed、尺寸等信息，本身就是线索
- **手动表格**：在实操笔记里记（就像本仓库 task 的「可复现参数记录」表）
- **导出工作流 JSON**：每张好图对应一份 Save 的工作流，见 [ch03 3.4](../../00_getting_started/docs/ch03_first_workflow.md#c03-04)
- **第三方工具**：有些节点/插件能把参数写进图片元数据（PNGInfo 类，按需）

一个够用的记录表字段：
```
模型 | seed | 提示词 | 负向 | steps | cfg | sampler/scheduler | 尺寸 | denoise | 备注
```

**常见误区**：
- ❌「图好看就行，不用记」—— 想复现或批量化时就会后悔。生成式创作「可复现」全靠记录。
- ❌「只记 seed 就够」—— 不够，模型/提示词/参数/版本缺一都可能出不来（[ch08 8.5](../../01_core_nodes/docs/ch08_ksampler.md#c08-05)）。

> **够用边界**：养成「好图就存一份工作流 JSON + 记关键参数」的习惯即可。
> **和已有认知的差异**：这更像**科研的记录规范**而非「随手保存文件」——
> 因为生成结果对参数极度敏感，没有记录就等于不可复现的偶然产物。这是这个领域的工程素养。

---

## 小结

- 文生图在 `Empty Latent Image` 设 `batch_size` 一次出多张；显存随 batch 线性增长。
- 调参锁 seed（控制变量）、挑图换 seed（探索）、复现靠**完整参数记录**。
- `Primitive` 节点一个值驱动多处（类型要匹配），像编程里的变量引用。
- 每张好图存工作流 JSON + 记参数表，否则无法复现。
