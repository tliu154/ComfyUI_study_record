### 4.1 节点的四个部件

**概念定义**：节点（Node）是工作流里的最小加工单元，每个节点长都差不多，由四部分组成：
- **输入端口（Input）**：节点左侧的小圆点，接收别人传来的数据
- **输出端口（Output）**：节点右侧的小圆点，把处理结果送出去
- **控件（Widget）**：节点内部的文本框、数字框、下拉菜单，是人手动填的参数
- **标题栏**：节点顶部，显示节点名（如 `KSampler`）

**直觉类比**：把节点想成一台**咖啡机**——
- 左侧输入口 = 加水口、加豆口（别人供给的原料）
- 右侧输出口 = 出咖啡的龙头（产物）
- 内部控件 = 你按的按钮（浓度、温度，手填的）
- 标题 = 机器上的型号标签

关键区分：**端口接的是「别处流来的数据」，控件填的是「你在这里写死的值」**。
比如 `KSampler` 的 `model` 是输入端口（接 `Load Checkpoint` 来的模型），
而 `steps=20` 是控件（你直接在这个节点里填的数字）。

**界面 / 参数**：观察 `Empty Latent Image` 节点——
- 它**没有输入端口**（不需要别人的数据）
- 三个控件：`width`、`height`、`batch_size`（你手填）
- 一个输出端口：`LATENT`（橙色的圆点，送出去）

再看 `Load Checkpoint`：
- 没有输入端口
- 一个控件：`ckpt_name`（下拉选模型）
- 三个输出端口：`MODEL`、`CLIP`、`VAE`

**常见误区**：
- ❌「控件也算输入」—— 概念上要分清：控件是**常量**（写死在这），端口是**变量**（别人喂进来）。
  这个区分在 ch12「用 Primitive 节点让一个值驱动多处」时会用到。
- ❌「所有节点都有输入和输出」—— 不一定。`Load Checkpoint` 只有输出，`Save Image` 只有输入。
  加载类节点是「源头」，保存/预览类节点是「终点」。

> **够用边界**：能看着一个节点认出「哪个是端口、哪个是控件」，知道端口收数据、控件填常量，就够了。
> 端口的类型系统下一节讲。
> **和已有认知的差异**：如果你写过 C++，一个节点很像**一个函数**：
> 输入端口 = 形参，输出端口 = 返回值，控件 = 函数内部写死的常量。
> 但节点不能「被调用」，它是常驻在图上、数据一变就重算——更像**电子表格里的一格公式**。

### 4.2 数据类型与颜色编码

**概念定义**：每条连线上流的数据都有**类型**。ComfyUI 用颜色把类型标出来，
所以你不用记类型名，看圆点颜色就知道能不能连。核心类型：

| 类型 | 颜色（常见） | 是什么 | 典型来源 → 去向 |
|---|---|---|---|
| `MODEL` | 蓝 | 扩散模型本体（去噪的大脑）| `Load Checkpoint` → `KSampler` |
| `CLIP` | 黄/棕 | 文本编码器 | `Load Checkpoint` → `CLIP Text Encode` |
| `VAE` | 紫/品红 | 图像编解码器 | `Load Checkpoint` → `VAE Decode` |
| `CONDITIONING` | 绿 | 编码后的提示词条件 | `CLIP Text Encode` → `KSampler` |
| `LATENT` | 橙 | 潜空间图像（压缩态）| `Empty Latent Image` → `KSampler` → `VAE Decode` |
| `IMAGE` | 紫/粉 | 真正的像素图像 | `VAE Decode` → `Save Image` |
| `MASK` | 灰/黑 | 蒙版（哪里要改）| 局部重绘用（[ch10](../../02_image_workflow/docs/ch10_inpainting.md)）|

**直觉类比**：类型就像**水管接口规格**——
热水管（MODEL）只能接热水口，煤气管（CONDITIONING）只能接煤气口。
颜色就是接口上的漆，防止你把煤气管插进热水口（那会出事）。
ComfyUI 直接**不让你连错类型**——拖线时颜色不匹配，圆点不亮、连不上。

**界面 / 参数**：怎么读 ch03 那条工作流的颜色——
```
Load Checkpoint
  ├─ MODEL(蓝) ──→ KSampler 的 model(蓝口)
  ├─ CLIP(黄) ──→ CLIP Text Encode 的 clip(黄口)
  └─ VAE(紫) ───→ VAE Decode 的 vae(紫口)

CLIP Text Encode → CONDITIONING(绿) → KSampler 的 positive/negative(绿口)
Empty Latent Image → LATENT(橙) → KSampler 的 latent_image(橙口)
KSampler → LATENT(橙) → VAE Decode 的 samples(橙口)
VAE Decode → IMAGE(粉) → Save Image 的 images(粉口)
```
读一遍你会发现：**颜色一致的线，类型就对**。这是排查连线的第一招。

**常见误区**：
- ❌「颜色在不同主题下不一样，记颜色没用」—— 颜色主题确实会变，但**同类型内部颜色始终一致**，
  关键是「同类同色、异类异色」，不是死记某个具体色值。端口名（如 `model`、`positive`）是更可靠的第二重线索。
- ❌「LATENT 和 IMAGE 都是图，应该能互连」—— 不能。LATENT 是压缩态（橙），IMAGE 是解码后的像素（粉），
  中间必须过 `VAE Decode`。这是新手最常踩的类型坑。

> **够用边界**：记住「同类同色、异类不能连」，能靠颜色大致判断连线对不对就够了。
> 各类型的数学本质（潜空间是什么）ch07 讲，现在不用懂。
> **和已有认知的差异**：这就是**强类型系统**的可视化版。C++ 里编译器拦 `int` 传给 `string*`，
> ComfyUI 里是端口颜色拦你连错——用意完全一样，只是从编译报错变成了「连不上」。

### 4.3 图是怎么被执行的

**概念定义**：你点 Queue Prompt 时，ComfyUI 不是随便乱跑节点，而是按**依赖关系**决定顺序：
一个节点要等它所有输入端口的数据都齐了，才能执行。
这样从「没有输入的源头节点」开始，一层层往后推，直到产出最终结果。
这种「节点 + 有向连线 + 不能成环」的图，叫**有向无环图（DAG, Directed Acyclic Graph）**。

**直觉类比**：像**流水线上的排班**——
- 没有前置工序的工位（如 `Load Checkpoint` 加载模型）最先开工
- 每个工位要等上工序的半成品到位才动手
- 两条并行的线（正向提示词、负向提示词）可以同时做，互不耽误
- 最后一道工序（`Save Image`）等所有料齐了才出成品

**界面 / 参数**：ch03 那条工作流的实际执行顺序（大致）——
```
第1批（源头，可同时）：Load Checkpoint、Empty Latent Image、两个 CLIP Text Encode（等 CLIP 到齐后）
   ↓
第2批：KSampler（等 MODEL + 正/负 CONDITIONING + LATENT 全齐）
   ↓
第3批：VAE Decode（等 KSampler 的 LATENT + Checkpoint 的 VAE）
   ↓
第4批：Save Image（等 IMAGE）
```
节点边框在运行时会依次高亮，你能**亲眼看到**这个顺序在画布上流动。

**常见误区**：
- ❌「节点是从左到右按顺序跑的」—— 不完全对。是按**依赖**跑，不是按你摆的位置。
  你把 `KSampler` 拖到最左边也一样等依赖齐了才跑。位置只影响阅读，不影响执行。
- ❌「能把输出连回前面的输入，做成循环」—— 不行。ComfyUI 不允许成环（那就是死循环）。
  若要迭代，得用专门的循环节点或多次 KSampler 串联（如 ch11 的二次采样）。

> **够用边界**：记住「等输入齐了才执行、按依赖不按位置、不能成环」三条就够了。
> DAG 的拓扑排序算法不用懂。
> **和已有认知的差异**：这和 C++ 的**顺序执行**完全不同——你写的语句是一行接一行跑；
> 这里是声明一张图，由引擎根据依赖自动排执行顺序。这叫**声明式 vs 命令式**的差别，
> 也是它灵活的原因（改一根线，执行顺序自动跟着变）。

### 4.4 连线的三条硬规则

**概念定义**：把前三节收口成三条你每次连线都在用的硬规则：
1. **一个输出 → 多个输入**：允许。一个 `CLIP` 可以同时喂给正向、负向两个编码器。
2. **一个输入 ← 仅一个输入**：一个输入端口只能接一根线，接新线会**顶掉**旧线。
3. **同类型才能连**：类型不匹配（颜色不同）根本连不上，引擎强制拦错。

**直觉类比**：
- 规则1 = 一个水龙头可以同时接多个杯子（分流 OK）
- 规则2 = 一个杯子只能接一根水管（不能两根管往一个杯子灌）
- 规则3 = 热水管口只对热水管（规格必须匹配）

**界面 / 参数**：实操中怎么用——
- **删线**：点一下连线选中，按 `Delete`；或从输入口拖出来丢到空处
- **替换输入**：直接从新输出拖到该输入，旧线自动断开
- **分流**：从同一个输出圆点拖出第二根、第三根线即可
- **看类型**：把鼠标悬停在端口上会显示类型名（不确定颜色时看这个）

**常见误区**：
- ❌「想把一个节点的结果接到两个 KSampler，结果第二个把第一个顶掉了」—— 检查你是不是接到了**同一个输入口**。
  要接不同节点的输入口，或同一节点的不同输入；一个输出分出多根线是允许的。
- ❌「线接错了但看不出来」—— 悬停端口看类型名；或看节点是否飘红（缺输入/类型错会标红）。

> **够用边界**：三条规则记牢，加上「悬停看类型、飘红查缺漏」两个排查动作，日常连线够用了。
> **和已有认知的差异**：C++ 里一个函数返回值你想赋给几个变量就赋几个（复制值）；
> 这里一个输出连多处，是**共享同一份数据流**（引擎会按需复用计算结果），
> 所以分流不会重复计算——这也是 ComfyUI 省算力的一个小原因。

## 小结

- 节点 = 输入端口（收数据）+ 输出端口（发数据）+ 控件（填常量）+ 标题。
- 类型用颜色区分：MODEL 蓝 / CONDITIONING 绿 / LATENT 橙 / IMAGE 粉…同类同色，异类连不上。
- 执行按依赖（DAG），不按摆放位置；节点等输入齐了才跑，不能成环。
- 连线三规则：一输出可接多输入、一输入只接一根、同类型才能连。
