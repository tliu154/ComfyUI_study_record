# 第 7 章 潜空间：图像在没解码前长什么样（Latent Space）

最后用 `VAE Decode` 把它「显影」成你能看的图片。

### 7.1 什么是潜空间（够用直觉）

**概念定义**：一张 512×512 的彩色图，在电脑里是 512×512×3 个数字（RGB 三通道）。
**潜空间（Latent Space）**是把它**压缩**后的表示——尺寸变成原来的 1/8（64×64），通道数变多。
在这个压缩空间里干活，计算量小很多，但保留了图像的关键信息。
diffusion 模型就在这个压缩空间里做去噪生成。

**直觉类比**：像**JPEG 压缩 / 快递打包**——
你要寄一床被子，直接寄又大又占地方（像素空间）；真空压缩后体积只有 1/8（潜空间），
寄起来快、省钱（算得快、省显存），到了对方那再拆包还原（VAE Decode）。
被子的「内容」没变，只是表示形式变了。

**界面 / 参数**：为什么不在像素空间直接生成？
- **算得快**：64×64 比 512×512 少 64 倍的位置要处理
- **省显存**：中间数据小，老显卡也能跑
- **效果够好**：VAE 压缩时保留了语义信息，解压后画质可接受

这就是「为什么工作流里有橙色的 LATENT 线，而不是一直用粉色的 IMAGE 线」的答案。

**常见误区**：
- ❌「潜空间是一个抽象概念，和我操作没关系」—— 恰恰相反，你动的每个尺寸参数、
  `Empty Latent Image`、`VAE Decode`、图生图的 VAE Encode，全在跟潜空间打交道。
- ❌「压缩会严重损失画质」—— VAE 是有损的，但训练时和 decoder 配套优化过，日常够用。

> **够用边界**：只要记住「**潜空间 = 图的压缩版，1/8 大小，在上面生成又快又省，最后要解码回图**」。
> 潜空间的数学定义、VAE 的训练目标、KL 散度这些，**全部可跳过**，不影响使用。
> **和已有认知的差异**：你写程序通常直接操作最终数据（像素）；这里引入了一个**中间表示层**，
> 所有计算都在压缩域做。这是 diffusion 模型的核心工程技巧，不是 UI 的花招。

### 7.2 EmptyLatentImage：造一张空白底

**概念定义**：`Empty Latent Image` 节点**创建一个空白的潜空间图**，作为生成的起点。
文生图时，它就是「一张还没画内容的画布」（压缩态的），你用 width/height/batch_size 定它的规格。

**直觉类比**：像**买一块空白画布**——你告诉店家要多大尺寸（width×height）、买几块（batch_size），
店家给你空白画布（空白 latent）。画布上现在是空的（其实是随机噪声），等着 KSampler 来「画」。

**界面 / 参数**：
- 控件：`width`、`height`（像素尺寸，如 512×512）、`batch_size`（一次造几张）
- 输出：`LATENT`（橙）
- 菜单路径：`model > latent > EmptyLatentImage`

关键：**这里填的 width/height 是最终出图的尺寸**。
图生图时（[ch09](../../02_image_workflow/docs/ch09_img2img.md)），这个节点会被 `Load Image + VAE Encode` 替代——
即「用已有图编码出 latent」而不是「造空白 latent」。

**常见误区**：
- ❌「尺寸随便填，越大越清晰」—— 尺寸要匹配模型训练分辨率：SD1.5 最佳 512×512，SDXL 最佳 1024×1024。
  乱填大尺寸可能出重复头/畸形。见 7.4。
- ❌「batch_size 越大越好」—— 一次出多张会线性增加显存占用，显存不够会 OOM。见 [ch12](../../02_image_workflow/docs/ch12_batch_seed.md)。

> **够用边界**：会填 width/height/batch_size，知道它是「空白潜空间底」就够了。
> 它内部为什么是填随机噪声——那是采样的起点，ch08 讲。
> **和已有认知的差异**：你在画图软件里新建画布，画布是「白色的」；这里的「空白画布」其实是**随机噪声**
> （一片雪花点），生成过程就是从这个噪声一点点去噪成图。这个反直觉点下一章讲透。

<a id="c07-03"></a>

### 7.3 VAE Decode：从噪声到像素

**概念定义**：`VAE Decode` 节点把 KSampler 处理完的**潜空间图（LATENT）解码成真正的像素图（IMAGE）**。
它是整条工作流的「显影」一步——前面所有计算都在压缩域，只有到这一步才变成你能保存、能看的图片。

**直觉类比**：像**照片显影 / 快递拆包**——
前面在暗房里处理的是底片（latent，你看不懂），`VAE Decode` 就是把底片洗成照片（IMAGE，能看能存）。
或者：压缩被子送到家，拆开真空袋（解码），恢复成能盖的被子。

**界面 / 参数**：
- 输入：`samples`（橙，接 KSampler 的 latent 输出）、`vae`（紫，接 Load Checkpoint 的 VAE 输出）
- 输出：`IMAGE`（粉）
- 菜单路径：`model > latent > VAE Decode`

配套的另一个节点 `VAE Encode`（反向）：把真实图片 IMAGE 编成 LATENT，图生图用（[ch09](../../02_image_workflow/docs/ch09_img2img.md)）。
一对编解码，Encode 进潜空间、Decode 回像素空间。

**常见误区**：
- ❌「VAE 忘了接，图也能出」—— 能出但颜色会发灰/发绿/异常，因为解码器不对。这是新手最常见的「图颜色怪」原因。
- ❌「VAE Decode 会改变画面内容」—— 正常不会，它只是把 latent 还原成像素。内容由前面的采样决定。
  换个不同 VAE 可能色调略有差异，但不改主体。

> **够用边界**：记住「VAE Decode = latent 变图片，必须接 VAE，漏接颜色会怪」就够了。
> VAE 的内部结构、编解码原理跳过。
> **和已有认知的差异**：这是整条链路里**唯一一次从压缩域回到真实像素**的地方。
> 理解这个「一直压缩 → 最后解压」的框架，图生图/重绘/放大（第 3 篇）就都好懂了——
> 它们本质上都是在 latent 的不同环节做文章。

### 7.4 尺寸、宽高比与显存

**概念定义**：出图尺寸不是随便填的，它同时影响**画质**（是否匹配模型训练分辨率）和**资源**（显存、耗时）。

**直觉类比**：像**裁照片**——相机的传感器有原生比例（模型训练尺寸），你硬要裁成奇怪的长宽比，
要么裁掉内容，要么拉伸变形。按原生比例附近来，效果最好。

**界面 / 参数**：常用尺寸表——

| 模型 | 推荐尺寸 | 说明 |
|---|---|---|
| SD 1.5 | 512×512 | 训练基准，最稳；可 512×768 等，别差太远 |
| SDXL | 1024×1024 | 训练基准 |
| FLUX | 1024×1024 附近 | 见 [ch20](../../04_models_and_lora/docs/ch20_workflow_variants.md) |

宽高比示例（SD1.5，面积大致接近 512×512）：
- 竖图：512×768（人像）
- 横图：768×512（风景）
- 方图：512×512

显存/耗时关系：
- **尺寸越大 → latent 越大 → 显存占用越高、越慢**（近似按面积增长）
- **batch_size 越大 → 显存线性增加**
- 显存不够 → 降尺寸 / 降 batch / 用低显存模式（[ch26](../../06_ecosystem/docs/ch26_performance.md)）

**常见误区**：
- ❌「尺寸填 2048 就会出超高清大图」—— 直接填大尺寸容易出畸形（重复肢体/构图崩）。
  正确做法是**先按推荐尺寸生成，再用放大流程**（[ch11](../../02_image_workflow/docs/ch11_upscale.md)）。
- ❌「尺寸和显存无关」—— 强相关。OOM 时第一个该降的就是尺寸。

> **够用边界**：记住「**SD1.5 用 512 系、SDXL 用 1024 系、想更大靠后期放大、显存不够先降尺寸**」。
> 这四条够日常用。分辨率与注意力的数学关系不用管。
> **和已有认知的差异**：你可能以为「数字越大越好」；这里尺寸是**和模型绑定的超参数**，
> 选对范围比选大更重要。这是经验性知识，靠查模型的推荐值。

---

## 小结

- 潜空间 = 图像的压缩版（1/8 大小），在上面生成又快又省，最后要 `VAE Decode` 解码成图。
- `Empty Latent Image` 造空白 latent（填尺寸/batch），是文生图的起点。
- `VAE Decode` 把 latent 显影成 IMAGE，必须接 VAE，漏接颜色会怪。
- 尺寸匹配模型（SD1.5=512 / SDXL=1024），想更大靠 ch11 放大，显存不够先降尺寸。
