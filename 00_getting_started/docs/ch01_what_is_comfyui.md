### 1.1 一句话认识 ComfyUI

**概念定义**：ComfyUI 是一个**基于节点的生成式 AI 界面和推理引擎**。
「基于节点」意思是：它不是给你一个输入框和几个滑块，而是把整个生成过程
拆成很多**功能单一的小方块（节点 Node）**，你自己用线把它们连成一张图（工作流 Workflow），
数据从左边流到右边，最后吐出一张图 / 一段视频。

**直觉类比**：把它想成**乐高**或者**厨房流水线**。
- 一个节点 = 一个工位：有人负责「把面粉拿来」（加载模型），有人负责「把话说清楚」（提示词编码），
  有人负责「揉面发酵」（采样去噪），有人负责「装盘上桌」（保存图片）。
- 连线 = 传送带：上一工位的成品放到传送带上，送到下一工位。
- 工作流 = 整条产线的排布图。你想换配方、加一步、跳过一步，直接动这块积木就行。

**界面 / 参数**：第一次打开你会看到三块区域（后面 [ch03](ch03_first_workflow.md) 会逐个带你看）：
- 中间的**画布 Canvas**：摆节点、连线的地方
- 左侧的**节点库**：搜节点名，点一下加到画布
- 右上角的 **Queue Prompt** 按钮：点它，整张图就从右往左执行一遍

**常见误区**：
- ❌「节点式 = 更难」—— 上手第一天的确比表单多点几下，但正因为「每步都摊开」，
  你反而能看懂图到底是怎么来的，排错也更容易。难点是**概念**，不是**操作**。
- ❌「ComfyUI 是一个模型」—— 不是。它是**跑模型的壳**，模型（checkpoint）要你自己下载放进去，见 [ch05](../../01_core_nodes/docs/ch05_loaders.md)。
- ❌「必须懂代码 / 懂数学」—— 上手阶段完全不用。本笔记的立场就是**够用就好**：先会搭、会改，原理按需补。

> **够用边界**：这一节只要记住「节点 = 积木，连线 = 传送带，工作流 = 产线图」这个画面就够了。
> 引擎内部怎么调度、DAG 是什么，第 4 章再讲，现在跳过毫无影响。
> **和已有认知的差异**：如果你写过 C++，这东西很像**数据流图 / 编译器的 IR 图**——
> 每个节点是一个 op，连线是数据依赖；也像 Unix 的 `cat a | grep x | sort`，
> 一个的输出喂给下一个的输入。你不是在「写」一张图，你是在「声明」数据怎么流动。

### 1.2 节点式 vs 一条表单（Node-based vs Form-based）

**概念定义**：主流的 AI 绘画界面有两大流派。
- **表单式**（以 Automatic1111 / WebUI 为代表）：一张大表单，正反向提示词、步数、CFG、种子……都填在同一个页面，点「生成」。简单直接。
- **节点式**（ComfyUI）：把这些步骤**拆开成独立节点**，你自己连线决定谁先谁后、谁连到谁。

**直觉类比**：
- 表单式像**微波炉**：一个面板，按几个键，加热。快，但你能调的就那几个按钮。
- 节点式像**开放式厨房**：灶台、烤箱、搅拌机分开摆，你决定先用哪个、怎么用、能不能同时开两个锅。
  自由度高，但要自己动手摆。

**界面 / 参数**：一个最小的对比——同样「文生图」，两种界面各自长这样：

| 维度 | 表单式（WebUI） | 节点式（ComfyUI） |
|---|---|---|
| 提示词 | 一个文本框 | `CLIP Text Encode` 节点 |
| 步数 / CFG / 种子 | 表单里的滑块 | `KSampler` 节点里的控件 |
| 加载模型 | 顶部下拉框选 | `Load Checkpoint` 节点 |
| 改流程顺序 | 基本不能 | 拖连线、加节点，随便改 |
| 显存占用 | 相对高 | 相对低，可控（见 [ch26](../../06_ecosystem/docs/ch26_performance.md)） |
| 上手难度 | 低 | 前 1~2 天略高 |
| 能做复杂流程 | 受限 | 几乎无上限（图生图、局部重绘、ControlNet、视频……） |

**常见误区**：
- ❌「节点式一定比表单式高级，应该一上来就用 ComfyUI」—— 不对。
  如果你只是偶尔出几张图、不想折腾，WebUI 或在线工具更省事。ComfyUI 的价值在**可控、可复现、可组合复杂流程**，
  当你开始问「能不能只改这块」「能不能固定种子批量跑」「能不能用参考图控制姿态」时，它的优势才显现。
- ❌「节点式出图质量更高」—— 节点式本身不提升画质，画质取决于模型、提示词、参数。
  它的优势是**给你控制权**，间接让你更容易调出想要的图。

> **够用边界**：你只要理解「表单式 = 固定流程填参数，节点式 = 自己搭流程」这个差别就够了。
> 具体有哪些节点、怎么连，第 2 章开始讲。
> **和已有认知的差异**：从 C++ / 写程序的角度，WebUI 像**调用一个封装好的大函数** `generate(prompt, steps, cfg...)`，
> 参数固定、黑盒；ComfyUI 像把这个函数**内联展开**成一步步的数据操作，你能看到、能改中间任何一步。

### 1.3 为什么值得学（Why ComfyUI）

**概念定义**：ComfyUI 在 2026 年已经是**重度用户的首选工具**（官方仓库十多万 star）。
值得学的理由可以归成四条，按「对新手的吸引力」排序：

**直觉类比**：如果说别人给你的是「一键出图」，ComfyUI 给你的是**整个暗房**——
你能控制显影的每一步。开始觉得麻烦，后来会觉得「回不去了」。

**界面 / 参数**：四条核心价值——

1. **可控**：每个环节都摊开。哪一步不满意，改那一步，不用重头猜。
2. **可复现**：一张工作流 JSON 文件 = 完整配方（模型、提示词、参数、连线）。发给别人，对方加载就能出一样的图。
   这对「我上次那张图怎么弄出来的」这种问题，是根治。
3. **省显存**：流程是按需执行的，中间结果用完可释放，显存占用通常比表单式低，老显卡也能跑大模型（配合 [ch26](../../06_ecosystem/docs/ch26_performance.md) 的技巧）。
4. **生态强**：图生图、局部重绘、ControlNet、LoRA、放大、视频、API 批量调用……新玩法几乎都是先在 ComfyUI 上实现。
   想学 advanced 玩法，绕不开它。

**常见误区**：
- ❌「学 ComfyUI 要先把 Stable Diffusion 原理、扩散模型数学全学会」—— 不用。
  这条路径是本末倒置。正确顺序是**先用起来，遇到看不懂的名词再回头补**，这也是整套笔记的组织方式（每章标「够用边界」）。
- ❌「工作流 JSON 是配置文件，改错了会坏」—— 它只是文本（JSON），大不了重新导出一份；改之前另存一份即可。

> **够用边界**：现在你只需要认同「可控 + 可复现 + 省显存 + 生态强」这四个字，作为投入学习的理由。
> 不需要记住任何技术细节。
> **和已有认知的差异**：如果你习惯了「软件应该开箱即用」，ComfyUI 更接近**开发工具**而非成品软件——
> 它给你能力，但要你自己组合。心态上把它当成「搭积木 / 写管线」而不是「用 App」。

### 1.4 硬件与运行环境（Hardware & Runtime）

**概念定义**：ComfyUI 本身很轻，真正吃资源的是**模型推理**这一步。
所以「能不能跑、跑多快」主要取决于你的显卡（GPU）和显存（VRAM）。

**直觉类比**：模型像一辆重卡，显存是油箱。油箱大（显存多）能拉重货、跑大图；
油箱小也不是不能开，但得少装点货（小分辨率、小模型、低精度），或者中途加餐（CPU 卸载）。

**界面 / 参数**：一个够用的判断表——

| 你的情况 | 能做什么 | 建议 |
|---|---|---|
| N 卡，显存 ≥ 8G | 主流 SD1.5 / SDXL 文生图，流畅 | 直接本地装，[ch02](ch02_installation.md) |
| N 卡，显存 4~6G | SD1.5 没问题，SDXL 要省着用 | 小分辨率起步，配合低显存模式 [ch26](../../06_ecosystem/docs/ch26_performance.md) |
| 显存 ≤ 4G / 无独显 | 慢，或跑不动大模型 | 先用云端 [ch02 2.4](ch02_installation.md#c02-04)，或量化模型 [ch18](../../04_models_and_lora/docs/ch18_model_files.md) |
| AMD / Intel 卡 | 能跑，但配置略麻烦 | 看官方仓库对应平台的安装说明 |
| Mac（Apple 芯片） | 走 CPU / Metal，能跑但偏慢 | 用 macOS 安装方式 |

要点：
- **NVIDIA 显卡体验最好**（CUDA 生态成熟），这是事实，不是偏好。
- **不要求联网出图**：模型下载到本地后，生成过程完全离线，隐私友好。
- **一定要有 Python 环境吗？** —— 用桌面版 / 便携包不用管；源码安装才需要，[ch02](ch02_installation.md) 会说清。

**常见误区**：
- ❌「显存不够就完全用不了」—— 有低显存模式、CPU 卸载、量化模型、小分辨率等多种办法，见 [ch26](../../06_ecosystem/docs/ch26_performance.md)。
- ❌「必须顶配显卡才能学」—— 学习阶段 SD1.5 + 512×512，6G 显存足够。硬件是「影响体验」，不是「决定能否入门」。

> **够用边界**：只要知道「看显存、N 卡最省心、不够也能用云端顶上」这三条就够了。
> 具体的低显存调参是第 7 篇的事，现在不用碰。
> **和已有认知的差异**：如果你写过 C++，习惯「编译一次到处跑」——这里不同，
> 同样的流程在不同显卡上要选不同精度 / 分块策略，硬件和软件参数是绑在一起的。

## 小结

- ComfyUI = 把出图拆成积木（节点），自己连线搭成流水线（工作流）。
- 它 vs 表单式工具的差别是「搭流程」vs「填参数」；价值在可控、可复现、省显存、生态强。
- 学习不用先啃原理；硬件看显存，N 卡最省心，不够可用云端。
