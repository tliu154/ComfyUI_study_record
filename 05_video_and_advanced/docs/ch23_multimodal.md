### 23.1 音频生成

**概念定义**：ComfyUI 通过自定义节点可以接入**音频生成模型**（如文本转音乐、文本转音效），
把音频当作工作流里的一种数据类型来生成和处理。

**直觉类比**：像**给工作流加一个"声音工位"**——
以前产线出图/视频，现在还能接一台"音频机"，按提示词产出音乐/音效，和画面流程并存。

**界面 / 参数**：
- 需要装音频相关自定义节点包 + 下载音频模型（见 [ch24](../../06_ecosystem/docs/ch24_manager.md)）
- 生成的音频可作为工作流输出保存
- 常和视频结合（给视频配乐/配音）

**常见误区**：
- ❌「ComfyUI 内置音频生成」—— 通常需要额外装节点包和模型，不是开箱即用。
- ❌「音频模型能直接用图像模型代替」—— 不能，是不同的生成任务和模型。

> **够用边界**：知道「ComfyUI 能靠自定义节点做音频，需要额外装」即可。真要做时再查当前生态。
> **和已有认知的差异**：数据类型从图像/视频扩展到音频——节点式系统的好处是「新模态 = 新节点」，
> 只要有人写了节点，就能接到同一张图里。这是可扩展架构的优势。

### 23.2 3D 生成

**概念定义**：ComfyUI 也能通过自定义节点接入**3D 生成模型**（如文本/图像转 3D 资产），
产出 3D 模型文件（如 glb/obj），用于游戏、建模等。

**直觉类比**：像**给产线加一台"3D 打印机"**——
以前只能出平面的图，现在能出立体的模型，你可以旋转查看、导进 3D 软件。

**界面 / 参数**：
- 需装 3D 相关节点包 + 模型（如 Hunyuan3D、TRELLIS 等，具体看当前生态）
- 输入可以是文字或图片，输出 3D 文件
- 与游戏引擎/建模软件配合（导出后继续加工）

**常见误区**：
- ❌「ComfyUI 直接建模」—— 它是生成 3D 资产的初稿，精细建模还要进专业软件。
- ❌「3D 生成和图像生成一样快」—— 3D 计算量更大，耗时/显存要求更高。

> **够用边界**：知道「能通过节点做文/图生 3D，产出资产初稿」即可，按需深入。
> **和已有认知的差异**：从 2D 到 3D 是又一个维度升级（像图像到视频多了时间，3D 多了深度）。
> 每种模态都对应不同的模型和节点，但都挂在同一个工作流系统下。

### 23.3 AI 智能体与 MCP

**概念定义**：**MCP（Model Context Protocol，模型上下文协议）**是一种让 AI 智能体（如 Claude 等）
连接外部工具的标准协议。ComfyUI 官方提供了 MCP 支持，意味着你可以**用自然语言让 AI 帮你搭/跑工作流**——
比如对智能体说「用这个模型生成一张赛博朋克风格的猫」，由它调用 ComfyUI 完成。

**直觉类比**：像**给工作流配一个"语音秘书"**——
以前你要自己点节点、填参数；现在你对 AI 说需求，它去操作 ComfyUI。
MCP 就是秘书和工具之间的"通用插座标准"。

**界面 / 参数**：
- 官方提供 Cloud MCP 服务器（托管在 cloud.comfy.org，[ch02 2.4](../../00_getting_started/docs/ch02_installation.md#c02-04)）
- 也可配置本地 MCP 连接你自己的 ComfyUI
- 让智能体调用图像/视频/音频/3D 生成能力

**常见误区**：
- ❌「MCP 是 ComfyUI 的一个节点」—— 不是，它是**外部智能体连接 ComfyUI 的协议/接口**，属于集成层。
- ❌「有了 MCP 就不用学工作流了」—— 相反，懂工作流才能给智能体下准确的指令、看懂它做了什么。

> **够用边界**：知道「MCP = 让 AI 智能体通过标准协议调用 ComfyUI，可用自然语言驱动生成」。
> 具体配置按需查官方文档。
> **和已有认知的差异**：前面都是「人操作 ComfyUI」；MCP 是「AI 操作 ComfyUI」——
> 你把 ComfyUI 从"人手工具"变成"智能体可调用的服务"。这是使用范式的转变，从操作者变成编排者。

### 23.4 Comfy CLI 与命令行

**概念定义**：`comfy-cli` 是官方命令行工具（[ch02 2.3](../../00_getting_started/docs/ch02_installation.md#c02-03) 提过），
除了安装/启动/更新，还能在终端调用模型生成（`comfy generate`）。
它让你**不打开浏览器**也能用 ComfyUI，适合脚本化和自动化。

**直觉类比**：像**从"点菜单"升级到"打电话下单"**——
浏览器界面是点菜单，命令行是打电话报需求，适合批量、自动、远程的场景。

**界面 / 参数**：
- `comfy launch`：启动；`comfy generate`：命令行生成（测试版，具体用法看官方最新文档）
- 配合 [ch25 API](../../06_ecosystem/docs/ch25_api_automation.md) 做更灵活的批量/自动化
- 适合写脚本、定时任务、服务器环境

**常见误区**：
- ❌「CLI 是给程序员的，我用不到」—— 学习阶段确实可跳过；但如果你想批量出图/自动化，它是更简单的入口。
- ❌「CLI 和 API 一样」—— CLI 是命令行工具（人敲命令），API 是程序接口（代码调用），相关但不同。

> **够用边界**：知道「comfy-cli 能在命令行安装/启动/生成，适合自动化；细节看官方文档」。
> 想做批量自动化时再深入，接 [ch25](../../06_ecosystem/docs/ch25_api_automation.md)。

## 小结

- ComfyUI 靠自定义节点扩展到音频、3D、MCP 等，都是「新模态=新节点」的可扩展思路。
- 音频/3D 需额外装节点包+模型，产出初稿/资产，按需深入。
- MCP = 让 AI 智能体通过标准协议调用 ComfyUI，用自然语言驱动生成；懂工作流才能下准指令。
- comfy-cli 支持命令行生成，适合脚本化/自动化，细节接 ch25。
