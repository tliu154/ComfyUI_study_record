### 16.1 工作流变大后的整理需求

**概念定义**：从 ch03 的 7 个节点，到加了 ControlNet、IP-Adapter、放大之后，
工作流很容易变成几十个节点、线交叉成网。这时候三个痛点出现：
**看不清**（线缠在一起）、**改不动**（牵一发动全身）、**不敢删**（不知道哪个节点还有用）。
节点整理技巧就是解决这三个痛点。

**直觉类比**：像**整理乱糟糟的桌面**——
一开始东西少随便放，多了之后要分类收纳（Group）、理顺电线（Reroute）、
把暂时不用的收进抽屉（Mute）。不是功能变了，是让东西好找、好用。

**界面 / 参数**：本章要学的四类工具——
- `Reroute`：理线（把一个输出分流成整齐的多路）
- `Group`（节点组）：分区（把相关节点框成一组，可整体移动/折叠）
- `Mute` / `Bypass`：临时禁用某节点做对比
- `Note`：贴备注（文字说明，不参与计算）

**常见误区**：
- ❌「整理只是好看，不影响功能」—— 布局确实不影响执行（[ch04 4.3](../../01_core_nodes/docs/ch04_mental_model.md#c04-03) 讲过按依赖执行），
  但**可读性直接影响你改对改错**，复杂工作流里非常实际。
- ❌「节点一多就必须整理」—— 按需。简单工作流不整理也没事。

> **够用边界**：知道「有这些工具、为解决乱/难改/不敢删」即可，具体用法下面各节。
> **和已有认知的差异**：这像代码的**重构与注释**——功能不变，但让结构清晰、可维护。
> 写程序你也会格式化、加注释、封装函数，这里是对「图」做同样的事。

### 16.2 Reroute 与 Group

**概念定义**：
- **Reroute（重路由）**：一个「中转点」节点，把一根线接进来，再从它分出多根，
  让密集的连线变得整齐有序。本身不改变数据。
- **Group（节点组）**：用框把一组相关节点圈起来，命名（如「ControlNet 分支」「放大段」），
  可整体拖动、折叠收起。

**直觉类比**：
- Reroute = **接线端子/排插**：一根总线进来，从排插分出几路，比从一点扯出一把线整齐
- Group = **收纳盒/文件夹**：把相关东西装一盒、贴标签，能整盒搬走、能盖上盖子先不看

**界面 / 参数**：怎么用——
- **Reroute**：加节点搜 `Reroute`（有的版本叫 `Reroute (Primitive)`），把输出接进它，
  再从它拖出多条线到各目标。适合一个输出要接很多地方时（如 CLIP 同时供多个编码器）。
- **Group**：框选一片节点 → 右键 → `Add Group`（或快捷键 Ctrl+G），命名；
  点组标题栏可折叠。可给不同组设不同颜色。
- **Note**：加 `Note` 节点写说明，放在关键节点旁边（如「这一段是 Hires-fix 二次采样」）。

**常见误区**：
- ❌「Reroute 会改变数据/影响结果」—— 不会，它纯粹是连线的中转，输出=输入。
- ❌「Group 折叠后节点就不执行了」—— 折叠只是隐藏显示，节点照常执行。想禁用要用 Mute（16.3）。
- ❌「Group 名字随便写」—— 写清用途（如「姿态控制」「高清修复」），下次打开一眼看懂。

> **够用边界**：会用 Reroute 把一条线分得整齐、会用 Group 分区+命名就够了。
> **和已有认知的差异**：Reroute 像代码里的「中间变量」（`tmp = f(); g(tmp); h(tmp)`），
> 避免重复调用、让依赖清晰；Group 像「函数/模块」的视觉边界，把一组相关操作打包成一个概念块。

### 16.3 Mute / Bypass 做 A/B 对比

**概念定义**：调试工作流时，常想「加/不加某个节点效果差多少」。
**Mute（静音）**和 **Bypass（旁路）**让你临时禁用节点而不删线：
- **Mute**：节点不执行，输出视为无（后续依赖它的节点可能报错，除非有替代路径）
- **Bypass**：节点被「短路」——输入直接透传到输出，跳过这个节点的运算

两者都能让你快速对比「有这个节点 vs 没有」的效果，试完一键恢复，不用删了再连回来。

**直觉类比**：像**音响的静音键 / 效果器的旁通踏板**——
- Mute = 静音：这个声道不出声
- Bypass = 效果器旁通：电流直接绕过效果器，声音不经过处理
试完再打开，一切照旧。

**界面 / 参数**：怎么用——
- 右键节点 → `Mute`（切换静音，节点变灰）或 `Bypass`（切换旁通）
- 快捷键：`Ctrl+M` 常用于 Mute（以版本为准）
- 典型用法：
  - 对比「加 ControlNet vs 不加」→ Mute 掉 Apply ControlNet（若有直连原始 conditioning 的备用路径）
  - 对比「用 vs 不用某个 LoRA」→ Bypass LoraLoader（输出直接透传，不施加 LoRA）
  - 排查报错 → 逐个 Mute 定位是哪个节点出问题

**常见误区**：
- ❌「Mute 和 Bypass 一样」—— 不同。Mute 让输出消失（下游可能报错），Bypass 让输入透传（下游还能收到数据）。
  LoRA 这类想「跳过但保持链路」的用 Bypass。
- ❌「禁用后忘了恢复」—— 出图不对时先检查有没有节点是灰的（被 Mute/Bypass 了）。

> **够用边界**：知道「Mute=禁用输出、Bypass=跳过但透传，用来做 A/B 对比和排错，试完恢复」。
> **和已有认知的差异**：这像代码里的**注释掉一段 / 开关某个 feature flag**——
> 不改结构就能对比有无某段逻辑的效果。是调试的必备手段，不是正式逻辑的一部分。

### 16.4 画布操作与快捷键

**概念定义**：一些提升效率的画布操作和快捷键，把「搭工作流」这件事变顺手。

**直觉类比**：像**用快捷键操作编辑器**——
会用快捷键的人效率翻倍，画布也一样，熟悉几个常用操作省很多事。

**界面 / 参数**：常用操作（具体以你版本为准）——
| 操作 | 作用 |
|---|---|
| 滚轮 | 缩放画布 |
| `Shift + 拖空白` | 平移视野 |
| 按 `N` | 打开节点库搜索 |
| 拖输出线到空白 | 自动弹出节点搜索并连线 |
| `Ctrl + 框选` | 多选节点 |
| `Ctrl + G` | 把选中节点成组 |
| `Delete` | 删除选中节点/连线 |
| `Ctrl + M` | Mute 选中节点 |
| `R` | 刷新模型列表（[ch05](../../01_core_nodes/docs/ch05_loaders.md#c05-03)）|
| 双击画布空白 | 快速搜索加节点（部分版本）|

其它技巧：
- **拖动节点时线会自动重排**，不用手动理
- **连线颜色**帮你核对类型（[ch04 4.2](../../01_core_nodes/docs/ch04_mental_model.md#c04-02)）
- **保存多份工作流**：不同实验存不同 JSON（[ch12 12.4](../../02_image_workflow/docs/ch12_batch_seed.md#c12-04)）

**常见误区**：
- ❌「快捷键都固定不变」—— 不同版本/分支快捷键可能不同，以实际为准，记常用几个即可。
- ❌「平移和缩放搞混」—— 滚轮缩放、Shift+拖平移；触屏/触控板手势因设备而异。

> **够用边界**：先记「N 搜节点、滚轮缩放、Shift+拖平移、Ctrl+G 成组、R 刷新」五个高频操作，够用。
> **和已有认知的差异**：节点编辑器的操作逻辑和 IDE/设计软件（VS Code、Figma）很像——
> 画布平移缩放、多选、成组，触类旁通。

## 小结

- 复杂工作流三痛点：看不清、改不动、不敢删；整理工具解决可读性。
- Reroute 理线（中转分流、不改数据）、Group 分区命名（可折叠、照常执行）、Note 贴备注。
- Mute=禁用输出（下游可能报错）、Bypass=跳过但透传（适合 LoRA 类），用来 A/B 对比和排错，试完恢复。
- 高频快捷键：N 搜节点、滚轮缩放、Shift+拖平移、Ctrl+G 成组、R 刷新。
