### 15.1 为什么要给词加权

**概念定义**：提示词里每个词对生成的影响不是平等的。默认情况下模型大致平均对待，
但你常常想让某个词「更重要」（如主体特征）或「次要一点」（如背景细节）。
**权重（weight）**就是给单个词/短语设一个倍数，调整它相对其他词的影响力。

**直觉类比**：像**点菜时强调重点**——
「我要一份牛排，**一定要七分熟**，配菜随便」（七分熟权重高）。
如果不强调，厨师可能把注意力平均分给所有要求，牛排火候就不准。

**界面 / 参数**：什么时候需要加权——
- 主体特征不够突出（如「戴帽子」总画不出来）→ 给帽子加权
- 某个词过度干扰（如背景词抢了主体）→ 给背景降权
- 多主体时区分主次 → 主要主体高权、次要低权

**常见误区**：
- ❌「所有词都加权」—— 都加等于都没加。只给**关键的少数词**加权。
- ❌「权重能解决一切问题」—— 加权是微调手段，模型能力、参考图（[ch13](ch13_controlnet.md)/[ch14](ch14_reference.md)）、参数（[ch08](../../01_core_nodes/docs/ch08_ksampler.md)）更根本。

> **够用边界**：知道「权重 = 让某些词更重要/次要」即可。
> CLIP tokenizer 如何切词、权重如何进注意力矩阵，跳过。
> **和已有认知的差异**：普通文本里词语是平等的；这里提示词是**带权重的条件向量**，
> 加权直接改变模型注意力的分配。所以提示词更像「调参」而非「写句子」。

### 15.2 权重语法与读法

**概念定义**：SD 生态（WebUI/ComfyUI 通用）的权重语法：
- `(word)`：默认加重约 1.1 倍
- `(word:1.3)`：加重到 1.3 倍
- `(word:0.8)`：减弱到 0.8 倍
- `((word))`：多重括号叠加加重（约 1.21 倍）
- `[word]`：减弱（老写法，逐渐少用）

**直觉类比**：像**乐谱的强弱记号**——
`(词:1.3)` = 这个音弹响一点（forte），`(词:0.7)` = 轻一点（piano）。
数字就是「音量倍数」，1.0 是正常。

**界面 / 参数**：写法示例（写在 `CLIP Text Encode` 的正向框里）——
```
a portrait of a woman, (red hat:1.3), (freckles:1.2),
soft lighting, (blurry background:0.7), highly detailed
```
读法：红帽子和雀斑要加强（主体特征），背景模糊稍微减弱（别抢戏）。

经验范围：
| 权重 | 效果 |
|---|---|
| 1.0 | 默认 |
| 1.1~1.4 | 温和加强，常用 |
| 1.5~2.0 | 强加强，可能过饱和/畸形 |
| 0.5~0.9 | 减弱 |
| <0.5 或 >2 | 容易出问题，慎用 |

**常见误区**：
- ❌「写成中文全角括号 `（词:1.2）`」—— 不生效，必须用**半角** `()` 和 `:`。
- ❌「`(词：1.2)` 用了全角冒号」—— 不生效，必须半角 `:`。
- ❌「权重无限调高」—— 过高（>1.5）常导致该特征过饱和、画面崩坏，1.1~1.4 通常够。

> **够用边界**：记住「`(词:1.2)` 加强、`(词:0.8)` 减弱、半角符号、1.1~1.4 够用」。
> 括号层数换算的精确倍数不必记。
> **和已有认知的差异**：这是嵌在自然语言里的**微型语法**，逗号分隔的词不是普通文本而是「带权条件项」。
> 写提示词更像写一份结构化的规格说明，而不是写作文。

### 15.3 顺序与组合的影响

**概念定义**：除了权重，**词的先后顺序**也影响生成——CLIP 编码时靠后的词通常权重略高，
重要主体放前面还是后面会有差别。另外短语的组合（用逗号分隔）比堆长句更清晰。

**直觉类比**：像**自我介绍的顺序**——
你把最想让人记住的身份放前面和放最后，别人印象不同。
提示词里「先说主体，再说细节/风格」通常比乱序更稳。

**界面 / 参数**：写法建议——
- **主体先行**：`a cute cat, sitting on a windowsill, sunlight, ...`（主体在前，细节跟上）
- **逗号分隔短语**，别写长句：`good: a cat, sunlight, detailed` ／ `bad: a cat that is sitting on the windowsill with sunlight`
- **重要词可放靠后或加权**：结合 15.2 的权重更可靠
- **风格词放后段**：`..., oil painting style, by van gogh`

**常见误区**：
- ❌「写成长句子效果更好」—— 通常相反，CLIP 对短语理解更好，长句容易稀释关键信息。
- ❌「顺序完全无所谓」—— 有影响但不如权重明显；重要特征建议既加权又放合适位置。
- ❌「英文语法要正确」—— 不必要，关键词堆砌（带逗号）反而常用，不必写完整句子。

> **够用边界**：记住「短语逗号分隔、主体在前、重要词加权」这套写法就够了。
> CLIP 的位置编码细节跳过。
> **和已有认知的差异**：这不符合自然语言阅读习惯——你不是在「写一个通顺的句子」，
> 而是在「列一串带权重的关键词」。放弃语法正确性，追求关键词精准，是提示词的思维转变。

### 15.4 易错点与可复现记录

**概念定义**：把提示词进阶的易错点收口，并强调**提示词也要纳入可复现记录**（[ch12 12.4](../../02_image_workflow/docs/ch12_batch_seed.md#c12-04)）。

**界面 / 参数**：易错清单——
| 易错点 | 正确做法 |
|---|---|
| 全角括号/冒号 | 用半角 `()` `:` |
| 所有词都加权 | 只给关键少数词加权 |
| 权重过高（>1.5）| 1.1~1.4 起步 |
| 长句堆砌 | 短语 + 逗号分隔 |
| 改了提示词没记下来 | 连同参数一起记录 |

可复现记录里，提示词要**原样保存**（含权重语法）：
```
模型 / seed / steps / cfg / sampler /
正向：a cat, (red hat:1.3), soft light, (blur bg:0.7)
负向：blurry, low quality
```

**常见误区**：
- ❌「提示词不用记，凭记忆」—— 权重语法细节多，不记下来根本复现不了。
- ❌「加权后就不用锁 seed 对照了」—— 恰恰相反，测权重效果更要锁 seed，一次只改一个词的权重（[ch08](../../01_core_nodes/docs/ch08_ksampler.md#c08-02)）。

> **够用边界**：把「半角符号 + 少数词加权 1.1~1.4 + 短语分隔 + 原样记录」这四条记牢，提示词进阶就够用。
> **和已有认知的差异**：这更像**配方管理**——提示词是一份需要精确记录和版本管理的「配方」，
> 而不是随手写的一句话。认真记录，是生成式创作的基本功。

---

## 小结

- 权重让某些词更重要/次要；只给关键少数词加，别全加。
- 语法 `(词:1.2)` 加强、`(词:0.8)` 减弱；**半角**符号；1.1~1.4 够用。
- 短语逗号分隔、主体在前、重要词加权；不必写通顺长句。
- 提示词连同权重语法原样纳入可复现记录；测权重也要锁 seed 单变量对照。
