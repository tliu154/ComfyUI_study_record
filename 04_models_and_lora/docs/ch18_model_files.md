### 18.1 常见模型文件格式

**概念定义**：模型文件有不同的**容器格式**，常见：
- **`.safetensors`**：目前主流，安全（不执行代码）、加载快，推荐优先选
- **`.ckpt`**：老格式（PyTorch checkpoint），能存代码，有安全风险，逐渐被替代
- **`.gguf`**：量化格式，常用于低显存/CPU 场景（尤其 FLUX/LLM 的量化版）

**直觉类比**：像**文件格式之争**（docx vs doc）——
safetensors 是安全的新格式（像 docx 不含宏病毒），ckpt 是老格式（像含宏的 doc，可能夹带代码）。
能用 safetensors 就别用 ckpt。

**界面 / 参数**：怎么选——
- 有 safetensors 版本 → **一律选 safetensors**（安全、快）
- 只有 ckpt → 用可信来源的，避免来路不明的文件
- 显存紧张 → 找 gguf / 量化版（见 18.2）

**常见误区**：
- ❌「格式影响画质」—— 同模型同精度下，格式只是容器，不直接影响画质。safetensors vs ckpt 画出来一样。
- ❌「随便下个 ckpt 就行」—— ckpt 可能夹带可执行代码，务必可信来源。safetensors 没这个问题。

> **够用边界**：记住「**优先 safetensors，避免来路不明的 ckpt，显存不够找 gguf/量化**」。
> **和已有认知的差异**：你平时选文件格式考虑兼容性；这里 safetensors 的「安全性」是硬指标——
> 因为老 ckpt 能藏代码，加载等于执行未知代码，这是真实风险，不只是偏好。

### 18.2 精度与量化怎么选（显存权衡）

**概念定义**：模型权重用多少位数字存储，叫**精度**。精度越低，文件越小、显存占用越少，但可能损失一点质量。
常见：fp32（少用）→ fp16（标准）→ fp8 / bf16 → 更低位的量化（int4/int8/gguf）。

**直觉类比**：像**照片的压缩质量**——
原图（fp32）最清晰但最大，高质量 JPEG（fp16）几乎无损，普通 JPEG（fp8/量化）更小但细节略降。
显存小就得用更压缩的版本，换来「能跑起来」。

**界面 / 参数**：选择表——
| 精度 | 显存 | 质量 | 适合 |
|---|---|---|---|
| fp16 | 标准 | 最佳 | 显存充足，首选 |
| bf16 | 标准 | 接近 fp16 | 部分新模型（FLUX）默认 |
| fp8 | 约省一半 | 略降 | 显存中等，FLUX 常用 |
| gguf / int4/int8 | 省更多 | 有可见损失 | 低显存 / CPU |

思路：**先试 fp16，显存不够再降精度**。FLUX 这类大模型常直接提供 fp8 版。

**常见误区**：
- ❌「精度越低越快越好」—— 降精度省显存，但画质有代价；够用就行，别一味压低。
- ❌「fp8 和 fp16 出的图一样」—— 通常有细微差别，大模型上更明显。
- ❌「量化能凭空变出显存」—— 只是用更少位存权重，质量换空间，不是无损。

> **够用边界**：记住「**fp16 首选、不够降 fp8、再不够 gguf；精度换显存有画质代价**」。
> 量化的位运算原理跳过。
> **和已有认知的差异**：这是典型的**空间-质量权衡**——和图像压缩、音频码率一个道理。
> 工程上「没有免费午餐」，省显存必然付出某种代价，你要做的是找到能接受的平衡点。

### 18.3 目录结构与放错位置的排查

**概念定义**：ComfyUI 靠**固定目录**找模型。放错目录 = 列表里看不到。
不同类型模型放不同子目录，加载器也对应不同目录。

**直觉类比**：像**图书馆分类上架**——
书必须放到对应分类号的书架，检索系统才找得到。放错架的书等于「丢书」。

**界面 / 参数**：`ComfyUI/models/` 下常用子目录——
| 子目录 | 放什么 | 对应加载器 |
|---|---|---|
| `checkpoints/` | SD1.5/SDXL 三合一 | `Load Checkpoint` |
| `diffusion_models/`（或 `unet/`）| FLUX/SDXL UNET | `Load Diffusion Model` |
| `clip/` | 文本编码器（CLIP-L/T5）| `Load CLIP` |
| `vae/` | 单独 VAE | `Load VAE` |
| `loras/` | LoRA | `LoraLoader` |
| `controlnet/` | ControlNet | `ControlNetLoader` |
| `ipadapter/` | IP-Adapter 模型 | IPAdapter 节点 |
| `clip_vision/` | CLIP Vision | IP-Adapter 配套 |
| `upscale_models/` | 放大模型 | `Upscale Model Loader` |

排查口诀（[ch05 5.3](../../01_core_nodes/docs/ch05_loaders.md#c05-03) 讲过）：
**放对子目录 → 按 `R` 刷新 → 下拉列表出现**。还不行检查文件名后缀是否正确（如 `.safetensors`）。

**常见误区**：
- ❌「模型放 `models/` 根目录就行」—— 不行，要放进对应子目录。
- ❌「新版本目录名可能不同」—— 对，不同版本子目录名有差异（如 unet/diffusion_models），以你界面实际为准。
- ❌「刷新了还没有 = 文件坏了」—— 先查路径和后缀，多数是放错位置或后缀不对。

> **够用边界**：记住「模型放 `models/` 对应子目录 + 按 R 刷新」这条口诀，够排查绝大多数「看不到模型」问题。
> **和已有认知的差异**：ComfyUI 用**约定优于配置**——靠目录位置决定模型类型，没有配置文件告诉它「这是什么模型」。
> 所以目录结构是硬约定，放错就找不到，不像有些软件能手动指定文件路径。

### 18.4 下载来源与命名规范

**概念定义**：模型从哪下、怎么命名，影响安全和长期管理。
常见来源：Hugging Face、Civitai，以及官方发布页。

**直觉类比**：像**买东西看渠道**——
正规渠道（官方/知名社区）有保障，来路不明的文件有风险。命名像贴标签，好找好管。

**界面 / 参数**：实用建议——
- **来源**：优先模型官方页 / Hugging Face 官方组织 / Civitai 高赞；看许可和评论
- **校验**：有的页面提供哈希值，下载后可校验文件完整性
- **命名**：文件名带家族/版本/精度，如 `sd15_v1-5_fp16.safetensors`、`flux1-dev-fp8.safetensors`，方便分辨
- **记录**：像 [ch12](../../02_image_workflow/docs/ch12_batch_seed.md#c12-04) 那样，记下哪个模型用于哪些图

**常见误区**：
- ❌「Civitai 上随便一个模型都安全」—— 看下载量/评分/作者，safetensors 更安全；ckpt 要格外小心。
- ❌「文件名随便，反正能加载」—— 模型多了以后，乱命名会让你分不清哪个是哪个，尤其同家族多版本时。

> **够用边界**：记住「可信来源 + safetensors + 文件名带家族/精度 + 好记的命名」。
> 哈希校验等进阶按需。
> **和已有认知的差异**：管理模型更像**管理依赖库**——你需要知道版本、来源、兼容性，
> 不能只堆文件。模型多了以后，命名和记录就是你的「依赖清单」。

---

## 小结

- 格式：优先 safetensors（安全快），避免来路不明 ckpt；显存不够找 gguf/量化。
- 精度：fp16 首选 → 不够 fp8 → 再不够 gguf；精度换显存有画质代价。
- 目录：模型放 `models/` 对应子目录 + 按 `R` 刷新；放错位置是「看不到模型」首因。
- 来源：可信渠道 + 好命名（带家族/精度），像管理依赖一样管模型。
