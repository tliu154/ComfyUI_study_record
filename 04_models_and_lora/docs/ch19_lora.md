### 19.1 LoRA 解决什么问题

**概念定义**：大模型（checkpoint）体积大、训练成本高。
LoRA（Low-Rank Adaptation，低秩适配）是一种**轻量微调**技术：只训练一小部分额外参数，
得到一个几十 MB 的小文件，加载后叠加到基础模型上，让它表现出特定风格/角色/概念。

**直觉类比**：像**给衣服加配饰**——
大模型是基础款衣服（贵、笨重），LoRA 是丝巾/胸针（便宜、小巧）。
你不换整件衣服，只加个配饰，整体风格就变了；换配饰比买新衣服便宜得多。

**界面 / 参数**：LoRA 常见用途——
- **风格**：某画家画风、某摄影风格、某动漫风格
- **角色/人物**：特定角色长相（配合触发词）
- **概念/物体**：特定物件、服装、姿势
- **细节增强**：画质、细节类 LoRA

**常见误区**：
- ❌「LoRA 能单独出图」—— 不能，它要**叠在 checkpoint 上**，没有基础模型就没法生成。
- ❌「LoRA 越大越好」—— LoRA 文件大小和效果不直接挂钩，看训练质量。
- ❌「所有 LoRA 通用」—— LoRA 和**模型家族/版本绑定**（[ch17 17.1](ch17_model_families.md#c17-01)），SD1.5 的 LoRA 不能给 FLUX 用。

> **够用边界**：记住「LoRA = 叠加在基础模型上的小配件，改风格/角色，不能单独出图，和家族绑定」。
> 低秩分解的数学完全跳过，当插件用。
> **和已有认知的差异**：你习惯「换功能就换整个程序/库」；LoRA 是「不改主体、热插拔小补丁」——
> 相当于给冻结的模型外挂一层可切换的增量。这是参数高效微调（PEFT）思想，近两年非常流行。

### 19.2 LoraLoader 接线与强度

**概念定义**：`LoraLoader` 节点把 LoRA 叠加到模型上。它吃 MODEL 和 CLIP，吐出加强后的 MODEL 和 CLIP，
你把这个输出接给后续节点即可。它有两个强度旋钮。

**直觉类比**：像**调鸡尾酒**——
基础模型是基酒，LoRA 是调味，`LoraLoader` 是调酒器。你决定加多少调味（强度），
调好的酒（输出 MODEL/CLIP）再倒给下一个环节。

**界面 / 参数**：接线骨架（插在 Checkpoint 和 KSampler 之间）——
```
Load Checkpoint(MODEL) → LoraLoader(model)
Load Checkpoint(CLIP)  → LoraLoader(clip)
LoraLoader(MODEL) → KSampler(model)          ← 用加强后的模型
LoraLoader(CLIP)  → CLIP Text Encode(clip)   ← 加强后的 CLIP（让触发词生效）
```
控件：
- `lora_name`：选 LoRA 文件（放 `models/loras/`，按 R 刷新，[ch18](ch18_model_files.md)）
- `strength_model`（0~1）：对**图像生成部分**的影响强度
- `strength_clip`（0~1）：对**文本理解部分**的影响强度（影响触发词识别）

**常见误区**：
- ❌「只接 MODEL 不接 CLIP」—— 很多 LoRA 需要 CLIP 一起加强才能识别触发词；两个都接。
- ❌「强度拉满 1.0」—— 常导致过拟合、画面僵硬或崩坏；风格类 0.6~0.8、角色类 0.7~1.0 起步试。
- ❌「LoraLoader 放在 KSampler 之后」—— 顺序错了，它要在模型/CLIP 进入采样器之前。

> **够用边界**：会照骨架接 LoraLoader、知道两个 strength 分别管图像和文本、0.6~0.8 起步。
> **和已有认知的差异**：两个独立的 strength（model/clip）是细节——
> 分开控制能微调「风格强度」和「触发词敏感度」，像一个旋钮管画面、一个管理解。这是 LoRA 特有的双通道。

### 19.3 触发词与权重配合

**概念定义**：很多 LoRA（尤其角色/概念类）有**触发词（Trigger Word / Activation Tag）**——
训练时绑定在特定概念上的特殊词，用的时候必须写进提示词，LoRA 才会「激活」那个概念。
触发词通常在下载页/作者说明里给出。

**直觉类比**：像**暗号**——
你请了个专人（LoRA）来画特定角色，但得说出暗号（触发词）他才知道你要画那个角色。
不说暗号，他只当普通要求处理，效果出不来。

**界面 / 参数**：怎么用——
- **查触发词**：看 LoRA 下载页（Civitai/Hugging Face）的 description / "trigger words"
- **写进正向提示词**：如某角色 LoRA 触发词是 `char_abc`，正向写 `char_abc, a person in park, ...`
- **配合权重**：触发词可加权 `(char_abc:1.1)`（[ch15](../../03_control_and_refine/docs/ch15_prompt_advanced.md)），但别过高
- **strength_clip**：太低可能导致触发词识别弱；角色类保持和 model 相近

**常见误区**：
- ❌「加载 LoRA 就自动生效，不用写触发词」—— 角色/概念类通常要写触发词才激活。
- ❌「触发词越加权越好」—— 过高会污染画面；按 LoRA 说明，通常 1.0~1.2 够。
- ❌「风格 LoRA 也要触发词」—— 纯风格类很多不需要特定触发词，看说明。

> **够用边界**：记住「**角色/概念 LoRA 看说明找触发词并写进正向提示词；风格类多半不用**」。
> **和已有认知的差异**：这是「条件激活」——LoRA 的能力不是无条件生效，而要靠提示词里的特定 token 触发。
> 这把「模型层」（LoRA）和「提示词层」（触发词）绑在一起，是角色类 LoRA 使用的关键门道。

### 19.4 多 LoRA 叠加与冲突

**概念定义**：可以同时加载多个 LoRA（如一个风格 + 一个角色 + 一个画质），
`LoraLoader` 节点**串联**：第一个的输出 MODEL/CLIP 接第二个的输入，依次叠加。
但多个 LoRA 可能互相影响甚至冲突。

**直觉类比**：像**叠穿衣服/调色**——
一件件叠加配饰可以搭出丰富效果，但堆太多、风格冲突（比如西装搭运动短裤）就乱了。
 LoRA 叠加也是「少而精」胜过「多而杂」。

**界面 / 参数**：串联接法——
```
Checkpoint → LoraLoader #1(角色) → LoraLoader #2(风格) → LoraLoader #3(画质) → KSampler
              ↑ 每个的 MODEL/CLIP 输出接下一个的输入
```
叠加建议：
- **总量克制**：2~3 个常见，太多容易崩
- **分类搭配**：角色 + 风格 + 画质是常见组合，各司其职
- **强度递减**：主体 LoRA 强度高些，辅助的（画质）低些
- **出现畸变** → 逐个 Bypass（[ch16](../../03_control_and_refine/docs/ch16_node_skills.md#c16-03)）定位是哪个 LoRA 的问题

**常见误区**：
- ❌「LoRA 叠得越多效果越好」—— 错，太多会互相干扰、画面崩坏、显存增加。
- ❌「多个 LoRA 触发词都堆上」—— 触发词太多会互相污染提示词，谨慎组合。
- ❌「叠加顺序无所谓」—— 顺序对结果有影响（尤其风格类），顺序不同效果可能不同。

> **够用边界**：记住「LoraLoader 串联叠加、2~3 个为宜、分类搭配、出问题用 Bypass 逐个排查」。
> 叠加的数学（多个低秩增量相加）跳过。
> **和已有认知的差异**：这像**图层叠加**——顺序和不透明度都影响最终效果。
> 多个 LoRA 是「多个增量补丁依次作用」，不是简单互斥选择，所以组合空间很大，也更容易冲突。

---

## 小结

- LoRA = 叠加在基础模型上的小文件，改风格/角色，不能单独出图，与模型家族绑定。
- LoraLoader 插在 Checkpoint 与 KSampler 之间，两个 strength 分管图像(model)和文本(clip)，0.6~0.8 起步。
- 角色/概念 LoRA 要按说明把触发词写进正向提示词；风格类多半不用。
- 多个 LoRA 串联叠加，2~3 个为宜，分类搭配；出问题用 Bypass 逐个排查。
