# 第 17 章 模型家族（Model Families）

主流家族有 SD1.5、SDXL、FLUX 等，各有最佳分辨率、提示词习惯和硬件门槛，选对了事倍功半。

### 17.1 一张表看清主流模型

**概念定义**：「模型家族」指一代 diffusion 模型及其生态（配套 CLIP/VAE、LoRA、ControlNet）。
不同家族不太能混用组件，所以换家族基本等于换一整套玩法。给一张够用的对比表：

| 家族 | 最佳分辨率 | 特点 | 显存门槛 | 提示词 |
|---|---|---|---|---|
| **SD 1.5** | 512×512 | 老牌、生态最全、LoRA/ControlNet 海量、跑得快 | 低（4~8G）| 英文关键词，常用负向词 |
| **SDXL** | 1024×1024 | 画质/细节更好、双 CLIP、构图理解强 | 中（8~12G）| 英文，更吃完整描述 |
| **FLUX** | 1024 附近 | 新一代、文字渲染/细节强、双 CLIP+T5 | 较高（12G+，可量化）| 自然语言句子，通常不用负向词 |
| **Z-Image / 国产新模型** | 见模型说明 | 部分中文友好、速度快 | 视模型而定 | 看具体模型 |

**直觉类比**：像**选相机**——
SD1.5 是轻巧的入门机（镜头配件最多、便宜），SDXL 是全画幅（画质更好、更贵），
FLUX 是最新旗舰（效果强、吃电）。没有绝对最好，看你拍什么、手里什么设备。

**界面 / 参数**：怎么选——
- **新手 / 显存小 / 想玩海量 LoRA** → SD1.5 起步（本教程前 16 章默认就是它）
- **追求画质 / 显存够** → SDXL
- **要文字渲染 / 最强细节 / 显存充足** → FLUX（工作流不同，见 [ch20](ch20_workflow_variants.md)）

**常见误区**：
- ❌「模型越新越好」—— 新模型门槛高、生态可能没 SD1.5 全。学习阶段 SD1.5 最稳。
- ❌「所有模型工作流一样」—— 不一样。FLUX/SDXL 的加载器和条件节点不同（[ch20](ch20_workflow_variants.md)）。
- ❌「一个家族的 LoRA 能给另一个用」—— 一般不能，LoRA 和模型家族绑定（[ch19](ch19_lora.md)）。

> **够用边界**：记住「SD1.5=512 快且生态全、SDXL=1024 画质好、FLUX=新且吃配置」三句话够选模型。
> 各家族的架构论文不必读。
> **和已有认知的差异**：这像编程语言的「版本/生态」——同一类工具，不同代之间 API（工作流）和库（LoRA）不完全兼容，
> 换版本要重新适配。不是简单换个文件就行。

### 17.2 SD1.5 与 SDXL

**概念定义**：这两个是 SD 系列的主力，理解它们的差别就理解了「为什么工作流会有变化」。

- **SD 1.5**：单文本编码器（CLIP-L），512 分辨率，生态最成熟。前面所有章节默认用它。
- **SDXL**：**双文本编码器**（CLIP-L + CLIP-G）、更大的 UNet、1024 分辨率，
  理解复杂提示词和构图的能力更强，细节更好。

**直觉类比**：SD1.5 是**一个翻译官**读你的订单；SDXL 是**两个翻译官**（一个管大意、一个管细节）一起读，
理解更到位——所以 SDXL 的提示词可以写得更像正常描述句，而 SD1.5 更吃关键词堆砌。

**界面 / 参数**：工作流层面的差别——
| 维度 | SD1.5 | SDXL |
|---|---|---|
| 加载 | `Load Checkpoint` 三合一 | 三合一或 UNET+CLIP+VAE 拆分 |
| 文本编码 | `CLIP Text Encode (Prompt)` | `CLIP Text Encode (SDXL)`（双 CLIP）或两路合并（[ch06 6.4](../../01_core_nodes/docs/ch06_conditioning.md#c06-04)）|
| 分辨率 | 512×512 | 1024×1024 |
| Refiner | 无 | 可选二次精修模型 |

**常见误区**：
- ❌「SDXL 只是分辨率大一点的 SD1.5」—— 不止，它是双编码器 + 更大 UNet，架构和工作流都变了。
- ❌「SD1.5 的提示词原样搬给 SDXL」—— 能用但发挥不出 SDXL；SDXL 更适合更完整的自然语言描述。

> **够用边界**：知道「SDXL = 双 CLIP + 1024，编码节点要换」即可。具体搭法在 [ch20](ch20_workflow_variants.md)。
> **和已有认知的差异**：这是「同一产品线的代际升级」，但升级点不只是数字（分辨率），
> 而是组件数量（1 个编码器 → 2 个），直接反映在工作流节点数上——这是节点式界面忠实反映模型架构的体现。

### 17.3 FLUX 的特点

**概念定义**：FLUX 是新一代扩散模型，特点是**文字渲染强、细节丰富、理解自然语言好**。
架构上和 SD 系列差别更大：用 **UNet + 双/多文本编码器（CLIP-L + T5-XXL）**，
通常**不靠负向提示词**（CFG 机制不同，常用 distilled 版本 CFG≈1）。

**直觉类比**：FLUX 像**换了套引擎的新车**——
不只是马力更大，连操作方式都变了（不用负向词、参数习惯不同）。你不能用开旧车的习惯直接开它。

**界面 / 参数**：FLUX 工作流的关键不同——
- **加载**：`Load Diffusion Model`（UNET）+ `Load CLIP`（CLIP-L）+ `Load CLIP`（T5）+ `Load VAE`，分开加载（[ch05 5.2](../../01_core_nodes/docs/ch05_loaders.md#c05-02)）
- **条件**：两个 CLIP 各编码一路，`Conditioning Combine` 合并（或专门节点）
- **参数**：distilled 版 `cfg≈1`、`steps≈20`、scheduler 常用 `simple`/`beta`（和 SD 的 euler+normal+cfg8 不同，[ch08](../../01_core_nodes/docs/ch08_ksampler.md)）
- **负向词**：一般留空

**常见误区**：
- ❌「FLUX 也写一堆负向词」—— 通常不用，distilled 模型 CFG=1 时负向词几乎不起作用。
- ❌「FLUX 用 Load Checkpoint 就行」—— FLUX 常见是分开的文件，要拆分加载（[ch20](ch20_workflow_variants.md)）。
- ❌「显存不够就没法碰 FLUX」—— 有 fp8 / 量化版（[ch18](ch18_model_files.md)），低显存也能跑，只是慢。

> **够用边界**：先记住「FLUX = 分开加载 + 双 CLIP + cfg≈1 + 不写负向词」，动手在 [ch20](ch20_workflow_variants.md)。
> 它的 rectified flow 数学跳过。
> **和已有认知的差异**：这是真正的「换范式」——不只是参数不同，连「要不要负向提示词」这个基本习惯都变了。
> 从 SD 转 FLUX 最大的坎是思维定式，不是技术。

### 17.4 许可与商用注意

**概念定义**：模型、LoRA、生成内容各有**许可协议（License）**，商用前必须看清楚。
ComfyUI 本身是 GPL-3.0 开源免费，但你加载的模型不一定是。

**直觉类比**：像**用素材做设计**——
软件免费不代表素材免费。你用免费软件剪辑，但用的音乐/字体可能有版权，商用要另授权。

**界面 / 参数**：常见许可要点——
- **模型权重**：不同模型许可不同（有的可商用、有的仅研究、有的要求署名），下载页会写，务必看
- **LoRA**：跟随其训练基底模型的许可，且可能有额外限制
- **生成内容**：多数模型许可允许商用生成物，但要核对；部分禁止特定用途
- **ComfyUI 本身**：GPL-3.0——如果你把 ComfyUI 打包进商业产品分发，需注意开源义务

**常见误区**：
- ❌「开源模型 = 随便商用」—— 不一定，开源也分很多许可证，条款不同。
- ❌「ComfyUI 免费 = 用它做的图都没问题」—— 生成的图还要看你用的**模型**许可，两回事。

> **够用边界**：记住「**商用前查模型许可页，ComfyUI 免费不等于模型随便用**」这条风险意识即可。
> 法律条款细读交给具体项目，本教程不做法律建议。
> **和已有认知的差异**：写普通程序你关心代码许可证；这里要同时关心**代码 + 权重 + 生成物**三层许可，
> 权重许可是最容易被忽略的一环。

## 小结

- 主流家族：SD1.5（512/快/生态全）、SDXL（1024/双CLIP/画质好）、FLUX（新/双CLIP+T5/cfg≈1/不写负向词）。
- LoRA、ControlNet 等组件和模型家族绑定，不能跨家族混用。
- 新手从 SD1.5 起步最稳；换家族意味着换一整套工作流和提示词习惯。
- 商用查模型许可；ComfyUI 免费 ≠ 模型随便用。
