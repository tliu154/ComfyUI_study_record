# 实操 18：整理模型目录与格式识别

> 对应章节：[第 18 章 模型文件与目录](../docs/ch18_model_files.md) ｜ 预计耗时：25 分钟
> 状态：`[已完成]`

## 目标

搞清楚自己模型文件的格式/精度，验证「放对目录 + 按 R 刷新」的排查流程，不下载新文件。

## 前提

- [ ] ComfyUI 装好，手里有至少 1 个模型文件

## 步骤

1. **识别格式**：打开 `models/` 各子目录，看你的模型文件后缀（`.safetensors`/`.ckpt`/`.gguf`），
   填进记录表。对照 [ch18 18.1](../docs/ch18_model_files.md#c18-01) 判断是否安全格式。

2. **识别精度**：从文件名找精度线索（fp16 / fp8 / bf16 / 数字量化），填表。对照 [ch18 18.2](../docs/ch18_model_files.md#c18-02)。

3. **验证刷新流程**：
   - 记下 `Load Checkpoint` 下拉里现有模型数
   - 把某个 checkpoint 文件临时移出 `checkpoints/` 到别处（如桌面备份），按 `R` → 它应从列表消失
   - 移回去，按 `R` → 它应重新出现
   → 这印证了「列表来自目录扫描 + 需刷新」（[ch18 18.3](../docs/ch18_model_files.md#c18-03)）

4. **（可选）放错位置演示**：把一个模型临时放到 `models/` 根目录（非子目录），按 R，确认它不出现在任何加载器列表——理解为何要放对子目录。

5. **检查命名**：看你的文件名是否带家族/精度信息；不符合的话，在记录表里写下更清晰的命名建议（不用真改名，避免破坏引用）。

## 验收标准

- [ ] 记录表填出格式、精度
- [ ] 移出/移回 + 按 R，验证模型列表随之变化
- [ ] 理解了放错子目录为何看不到模型

## 改一改会怎样（小实验）

| 改动 | 预期现象 | 为什么 |
|---|---|---|
| 模型放 `models/` 根目录 | 任何加载器都看不到 | 必须放对应子目录，见 ch18 18.3 |
| 放了新模型不按 R | 列表里没有 | 需刷新重扫，见 ch18 18.3 |
| 选 fp8 而非 fp16（FLUX）| 显存省但细节略降 | 精度换显存，见 ch18 18.2 |

## 常见问题

- 列表看不到模型 → 查子目录 + 后缀 + 按 R，见 [ch18 18.3](../docs/ch18_model_files.md#c18-03)
- 不确定精度 → 看文件名关键词或下载页说明
- 想下新模型 → 可信来源（见 [附录 D](../../90_appendix/docs/appD_resources.md)），优先 safetensors
- 其它 → [附录 C 故障排查](../../90_appendix/docs/appC_troubleshooting.md)
